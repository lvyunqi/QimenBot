# Web 管理面板

QimenBot 自带一个本地 Web 管理面板。它把常用的运行操作、结构化日志、插件管理和配置编辑集中到浏览器中，适合本机调试，也适合在内网服务器上做日常维护。

面板只管理 QimenBot 自己的运行状态，不会替代 QQ 开放平台控制台。官方 QQ Bot 的 AppID、事件权限和审核状态，仍然要在 [QQ 开放平台](https://q.qq.com/) 中配置。

## 启动和访问

默认配置已经启用面板，并且只监听本机：

```toml
[admin_web]
enabled = true
bind = "127.0.0.1:3210"
access_token = ""
log_capacity = 2000
audit_path = "config/admin-audit.jsonl"
```

启动宿主后，在本机浏览器打开：

```text
http://127.0.0.1:3210
```

如果你修改了 `bind` 或 `enabled`，需要重启宿主后才会开始监听新的地址。面板页显示“需要重启”时，说明文件已经保存，但当前进程还在使用旧配置。

### 在其他设备访问

只有在确实需要远程维护时，才把监听地址改成内网地址。例如：

```toml
[admin_web]
enabled = true
bind = "192.168.1.20:3210"
access_token = "${QIMEN_ADMIN_TOKEN}"
```

绑定非回环地址时，`access_token` 不能为空，否则宿主会在启动时拒绝配置。建议把 Token 放进环境变量，不要直接写入仓库：

```powershell
$env:QIMEN_ADMIN_TOKEN = "请替换为随机长字符串"
cargo run
```

```bash
export QIMEN_ADMIN_TOKEN='请替换为随机长字符串'
cargo run
```

通过反向代理暴露面板时，仍然要保留 Token，并在代理层启用 HTTPS、限制来源 IP。不要把 `3210` 直接暴露到公网。

## 首页怎么看

首页显示 Bot 连接数、事件和回复统计、实时事件以及宿主健康状态。状态徽标只表示当前进程观察到的状态：

| 徽标 | 含义 |
| --- | --- |
| 绿色 | 已连接、已启用或操作成功 |
| 黄色 | 正在连接、等待重试或保存后需要重启 |
| 红色 | 连接或操作失败 |
| 灰色 | 已关闭、未配置或暂时没有数据 |

数字会随轮询和日志流更新。页面显示“宿主运行中”并不代表每一个 Bot 都在线，具体连接状态要看机器人列表。

## 配置页

配置页按用途分成六个分区。顶部的摘要徽标可以直接跳到常用分区，左侧标签也支持键盘切换。

### 运行时

这里维护运行环境、日志级别、关闭超时、任务宽限、日志缓冲容量和 JSON 终端日志。数字输入框右侧的单位是配置文件实际使用的单位，例如“秒”“条”和“ms”，不需要手动换算。

### 面板安全

这里修改面板开关、监听地址、审计日志路径和管理 Token。面板默认建议保持 `127.0.0.1`。监听地址改为非回环地址后，必须同时配置 Token。

### 模块与插件

内置模块和静态插件会显示成徽标。徽标文字就是配置文件中的模块 ID：

1. 在输入框键入一个 ID，按回车或点击加号添加。
2. 点击徽标右侧的删除图标移除。
3. 修改只会留在浏览器草稿中，点击“保存”后才写入 `config/base.toml`。

动态插件的 DLL、SO 或 dylib 目录以及插件状态文件也在这个分区配置。动态插件的启用、禁用和热重载，使用“插件”页面的操作按钮完成。

### 插件商城

商城目录固定使用 QimenBot 主仓库自动发布的官方索引，这里只配置商城开关、审核缓存、安装锁、请求超时和预发布通道。商城默认开启，但只在打开商城或手动刷新时访问目录。第三方插件自动更新当前固定为关闭，更新需要管理员逐次确认。

缓存目录保存下载资产和可回滚的历史二进制；安装锁记录仓库数字 ID、版本、target、SHA256 和固定状态。两者都应放在持久化磁盘并纳入备份。完整安装、关联本地插件、回滚和投稿说明见[插件商城](/plugin/marketplace)。

### Webhook

这里维护 API 0.5 动态插件 Webhook Gateway 的开关、监听地址、基础路径、Bearer Token、请求体上限、请求超时和并发上限。Webhook 默认关闭并监听本机。完整路由规则见 [API 0.5 Webhook Gateway](/advanced/dynamic-webhook-v05)。

### 配置版本

每次保存前，宿主会先备份当前配置，并保留最近的版本。版本徽标中的短 ID 用于区分备份；当前版本的“恢复”按钮会被禁用。需要撤销最近一次保存时，选择目标版本并点击“恢复”，然后按页面提示重启宿主。

## 保存、撤销和密钥

配置页底部的操作条会一直显示当前状态：

- “配置与磁盘一致”表示没有未提交修改。
- “有未保存更改”表示浏览器里有草稿，刷新或撤销会放弃这些修改。
- 点击“保存”后，宿主会先解析 TOML、执行配置校验，再创建备份并写入文件。校验失败时不会覆盖原文件。

管理 Token 和 Webhook Token 是只写字段。接口只返回“已配置”或“未配置”徽标，不会把原值发回浏览器：

- 输入框留空，保存时保留原来的 Token。
- 输入新值并保存，才会替换原值。
- 刷新或撤销会清空尚未提交的密钥草稿。

## 其他页面

### 机器人

机器人页展示每个实例的协议、传输方式、连接状态和最近错误。可以对单个实例执行启动、停止和重连，也可以打开编辑器修改该 Bot 的连接和权限配置。涉及监听地址、协议或鉴权的修改通常需要重启。

### 实时日志

日志页读取宿主的结构化日志缓冲，并通过 SSE 接收新记录。可以按级别、目标和关键词筛选。日志缓冲容量由配置页的“日志缓冲容量”控制；重启后，内存中的旧记录会清空。

### 插件

插件页列出静态模块和动态插件的版本、API 兼容性、命令与路由。动态插件支持启用、禁用和热重载。热重载失败时，旧实例不会被悄悄替换，详情会写入日志和审计记录。

### 插件商城

商城页读取 GitHub 托管的审核目录，并根据当前 QimenBot、动态 ABI、target 和 glibc 标记版本兼容性。安装、更新、关联、固定、回滚和卸载都会写入审计日志。卸载只移除活动动态库，插件配置和数据由管理员另行备份与清理。

### 版本更新

版本更新页会先判断部署方式：

- 显示“QimenBot 托管运行”时，可以检查 Release、确认安装和优雅重启。
- 显示“Docker 编排托管”时，页面只显示当前部署说明。镜像更新要在宿主机执行 `docker compose pull` 和 `docker compose up -d`。
- 显示“直接启动二进制”时，当前进程没有可靠的替换和回滚监督者。退出后改用 `qimenbot run` 启动。

安装按钮只负责程序文件，不修改机器人配置、插件目录和数据库。下载、校验、关闭、启动、健康检查或回滚中的当前阶段都会显示在页面上。

### 审计

审计页记录 Bot、插件和配置管理操作。文件路径由 `audit_path` 控制，默认是 `config/admin-audit.jsonl`。审计记录不包含 Token 原文。

## 常见问题

### 浏览器能打开页面，但 API 返回 401

这是远程绑定启用了 Token 的正常表现。访问页面后，在登录提示中填写与 `admin_web.access_token` 完全一致的值。不要把 Token 放进 URL 或截图。

### 页面显示“需要重启”

配置文件已经成功保存，但部分设置只在宿主启动阶段读取。使用 `qimenbot` 部署时，在“版本更新”页点击“优雅重启”；直接开发运行时再手动重启 `qimenbotd`。不要连续点击保存来尝试即时生效。

### 配置保存失败

先查看页面的错误提示和实时日志。常见原因包括监听地址格式错误、非回环监听缺少 Token、数值为零或模块 ID 不存在。修正后再保存，原配置不会被半写入覆盖。

### 看不到最新日志

确认宿主进程仍在运行，并检查浏览器是否被代理或扩展拦截了 SSE 连接。日志页只显示当前进程缓冲中的记录，重启后不会恢复旧日志文件。

## 安全清单

1. 本机使用时保持 `bind = "127.0.0.1:3210"`，并让 `access_token` 留空或配置环境变量。
2. 远程使用时设置长随机 Token、限制防火墙来源，并通过 HTTPS 反向代理访问。
3. 不要把 AppSecret、管理 Token 或 Webhook Token 提交到 Git，也不要贴到 issue、群聊和截图中。
4. 共享日志前先检查是否包含账号 ID、请求头或第三方错误详情。
